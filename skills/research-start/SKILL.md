Start with: Research idea or question, project directory, existing records and constraints.

## Do

1. Inspect existing records before creating anything. If this is paused work, use [research-resume](../research-resume/SKILL.md) and continue from its next decision; do not restart the project.
2. Use [research-grill](../research-grill/SKILL.md) to settle the question, success criterion, baseline, constraints and decision owner. Ask only decisions that block the next useful experiment.
3. Use [component-design](../component-design/SKILL.md) to define useful pipeline boundaries, contracts and source mappings. Reuse an existing hierarchy; do not invent one component per function or layer.
4. Use [research-wayfinder](../research-wayfinder/SKILL.md) to choose the next experiment. Queue literature review or EDA only when missing evidence blocks that decision.
5. Save the brief, component manifest and next step through those skills' output contracts. Do not train, change implementation or create approval records on the researcher's behalf.

## Deliver

A settled research question, reusable component structure and one next experiment or named blocker. Reuse existing records instead of adding a parallel startup record. [Checklist](assets/output.md).

## Stop

Finish when the next action and its decision owner are clear. Starting research does not authorize implementation or expansion of component scope. Invoke the next phase only when its inputs exist.
